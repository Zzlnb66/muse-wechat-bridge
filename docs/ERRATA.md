# 外部方案对比与常见误区勘误（Errata）

针对社区流传的“Muse 接入微信”通用分析文章与脚本教程，以下明确说明本项目（自研 `bridge.py` 修复版）的实际工程实现差异，避免开发与运维误判：

## 1. 声明：代码完全自研，仅参考腾讯协议文档

- **误区**：认为本项目复用或衍生自 `DONGH4O/wechat-ilink-bridge`、`cooooooooooode/weixin-clawbot-bridge` 或 `NewFuture/openclaw-weixin`。
- **事实**：本项目仅参考 `Tencent/openclaw-weixin` 仓库中的协议说明（`docs/protocol.md`）。核心 `bridge.py`（包含登录鉴权、本地队列、消息去重、图片 AES 加解密、发送状态机）均为从零编写的 Python 实现（详见 `THIRD_PARTY_NOTICES.md`）。切勿在 Muse 会话中使用包含第三方桥接仓库链接的部署提示词，以免覆盖或污染现有自研代码。

## 2. 登录方式：本地导出 `session.json` 上传（非云端直接扫码）

- **误区**：在 Muse 云端沙箱内直接生成二维码图片并在聊天窗口扫码登录。
- **事实**：实测云端二维码均在约 2 分钟内过期，且鉴权 POST 请求在云端环境会出现挂起。本项目的标准跑通路径为：**在本地 Windows 环境运行登录获取凭据，再将生成的 `session.json` 上传至云端工作目录**。

## 3. 时延结构：45s 长轮询 + 5s Hook + 1s 发送排空

- **误区**：认为系统存在“35s 长轮询 + 15s Hook + 15s 启动 = 固定 1~2 分钟”的机械时延。
- **事实**：
  - **iLink 长轮询超时**：`45 秒`
  - **Muse Hook 轮询间隔**：`5 秒`（系统支持的最低间隔）
  - **出站发送线程排空**：`1 秒`
  - **真实耗时分布**：发送线程投递单条纯文本仅需 **1～2 秒**。端到端感知的等待时间（几十秒至 2～3 分钟不等）主要取决于 **Muse Worker 本身的推理生成耗时**（如多模态看图、复杂工具调用）以及 **媒体文件传输耗时**（针对大图下载中 `urllib` 截断问题，已内置 `curl` 降级救回机制）。

## 4. 会话激活：`context_token` 强校验（防 `ret -2`）

- **误区**：首次扫码后发消息只是为了“激活聊天窗口”或传递普通会话 ID。
- **事实**：iLink 发送接口强制要求携带入站消息下发的 `context_token`。首次绑定后必须先由微信端主动发送一条入站消息，桥接层捕获并持久化该 `context_token`，后续所有出站回传请求必须原样带回该字段，缺失或失效会直接触发 `ret -2` 发送失败。

## 5. 并发去重与多图收发机制

- **单实例与去重**：通过 `flock` 文件锁保证全局单实例运行，配合 `message_id` 严格去重与**整批处理完后游标后移**机制，避免同一指令重复触发回复。
- **多图拆分特性**：在微信端一次勾选发送 2 张图片时，iLink 协议底层会将其拆分为 **2 条独立的单图消息** 依次下发，测试与排查日志时需按两条独立消息核对（详见 `docs/testing.md`）。

## 6. 合规与风险边界声明

- **规范表述**：本项目通过微信客户端内置的 `ClawBot` 灰度插件及官方 `ilinkai.weixin.qq.com` 通道完成扫码授权。该方式虽无传统第三方逆向协议（Hook/外挂）的破解风险，但 `ClawBot` 仍属平台灰度能力，**不代表永久免责或零风险**，账号可用性仍受腾讯/微信平台规则变化约束（详见 `README.md` 与 `SECURITY.md`）。
